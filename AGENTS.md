# CloudLibrary project instructions

## Changelog maintenance

- Update `CHANGELOG.md` for every completed UI, product, backend, database-rule, configuration, test, or documentation change.
- Put work that has not been released under `Unreleased`, grouped as Added, Changed, Fixed, Security, or Verification when useful.
- Move Unreleased entries into a dated section only for an approved release or clearly named checkpoint.
- Include the changelog update in the same commit as the change it documents.
- Do not describe incomplete experiments as completed work.
- Before committing, verify that the staged diff contains the appropriate changelog entry. A changelog-only maintenance commit is the sole exception.
